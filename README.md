# 弈间 Go Studio

React、TypeScript、Three.js 开发的个人围棋学习游戏。包含可旋转的 3D 棋盘、指导课程、练习、经典开局、本地对弈和可自行配置的个人 AI。

## 本地运行

建议使用 Node.js 22.12 或更新版本。

```powershell
npm ci
npm run dev
```

打开 http://127.0.0.1:5186/。如果端口被占用，可以使用 `npm run dev -- --port 5188`，以终端显示的地址为准。

```powershell
npm run test
npm run build
npm run preview -- --port 5187
```

生产构建写入 `dist/`，可部署到普通静态网站服务。使用 Web 服务打开，不直接双击 HTML；正式部署使用 HTTPS，本机回环开发地址可以使用 HTTP。生产版首次加载并完成 Service Worker 缓存后，可离线打开课程、题目和本地对弈；开发服务器不提供完整离线缓存。

## 当前功能

- 八阶段、32 节课程；96 道课内题、48 道阶段测试和 8 道独立入门测评。
- 棋盘操作、三级提示、讲解演示、无提示答题、错题与间隔复习。
- 完整征子与引征对比、枷吃、倒扑、真假眼、两眼、双活与死棋变化。
- 六种经典开局：二连星、三连星、中国流、小目守角、星小目组合、对角型布局。支持逐手播放、拖动手数和棋盘跟练。
- 五路教学盘，以及九路、十三路和十九路对弈。材质、灯光、接触阴影、落子动效、俯视、旋转、缩放、十九路平移与局部预览。
- 本地 Worker 对手；四种策略档位、指导练习和独立挑战、执子与贴目设置。
- 个人 AI 的 Base URL、API Key、模型、超时和回复上限配置，以及连接测试和局面问答。
- 对局自动保存、恢复、悔棋、停着、认输、死子确认、面积计分、复盘分支和 SGF 导出。
- 浏览器 IndexedDB 保存进度与棋谱；AI 配置独立存储；同一棋局的多标签编辑锁定。
- 手机布局、深色主题、减少动效、键盘操作、落子确认及 2D 降级。
- 竹林晨光、室内棋室、夜庭灯火三种本地 3D 场景；榧木、胡桃木、银灰岩石棋盘可随时切换。
- 全局围棋教练：读取当前课程、棋盘和棋谱步骤注解，支持连续追问、停止请求和复制回答。未配置 AI 时提供本地课程与局面提示；独立测评禁用辅助。
- 九份注解教学谱，包含九路 30 手示意、十九路方向比较及提子、假眼、两眼、征子、倒扑变化；可以选择分支、逐手播放、导出 SGF、转入个人复盘试下。
- UTF-8 SGF 导入：支持多盘集合、根节点设子、注解、停着与变化分支；导入棋谱保存到本机。中途设子、非标准板型和不符合本站规则的谱会给出错误提示。
- 六类小游戏：手筋冲刺、征子追击、倒扑实验、眼形侦察、收官练习场、布局方向感。题图支持八种对称方向和执子交换，可限时挑战或自由练习；使用提示或教练的轮次不更新无辅助最佳成绩。
- 完整存档可导出并快速加载：学习与复习进度、挑战成绩、全部棋谱及分支、界面偏好、AI 配置。可选择包含明文 API 密钥；加载前预览并验证，可合并学习成果并保留已有同 ID 棋局，也可恢复为存档当时的状态。

## AI 接入

在“我的空间”填写兼容 chat-completions 的 API 根地址，例如 `https://你的服务/v1`，然后输入密钥与模型，保存并测试连接。请求端点为根地址加 `/chat/completions`。密钥可以仅在当前页面使用，也可以明文保存在当前浏览器。

配置不发送给应用后端；实际 AI 请求会将认证信息和必要的当前棋局发送给用户指定的服务。没有账号、云端配置同步或内置统计服务。导出的学习进度与 SGF 不含密钥。

“完整存档”另外包含 AI 配置，默认不包含密钥。勾选“包含 API 密钥”后文件会包含明文密钥，适合自己迁移设备。导入时遵循存档的“记住密钥”选项：关闭记住时，恢复的密钥仅供当前页面使用，刷新后清除。

AI 只选择本地规则允许的候选动作，回复必须匹配局面摘要和请求标识。每轮最多两次调用；失败时明显标记本地接手。通用语言模型的输出不作为规则、死活或胜率的权威，默认落子讲解来自可验证的本地事实，自由问答单独标记为 AI 建议。

四种档位对应不同战术、有限搜索和采样配置，尚未完成正式棋力校准，不能换算为段级位。KataGo 等专业引擎接入属于后续增强项。

本地对手在 Worker 中评估棋块安全、连接、眼形与短程势力，进行完整深度的分支搜索；九路和十三路另外使用规则校验的蒙特卡洛试下。按档位设置时间预算，未完成的搜索层或试下批次不会偏向先检查的候选。默认入门档在四盘与初始版本的诊断对局中获胜；该样本小、终局使用未经死子裁定的面积计数，仅用于回归观察，不是棋力认证。十九路当前使用局部搜索，复杂征子与死活仍需人工验证。

### 服务不允许浏览器跨域时

可以在自己的电脑运行附带代理。代理只监听回环地址，不保存密钥，也不记录请求正文；认证头由浏览器传来，再转发给自己指定的上游服务。

```powershell
node scripts/local-ai-proxy.mjs https://你的服务/v1
```

页面中的 Base URL 改为 `http://127.0.0.1:5190/v1`，密钥和模型仍按上游服务填写。可用 `GO_PROXY_PORT` 修改监听端口，`GO_ALLOWED_ORIGINS` 设置逗号分隔的页面来源。模型请求依旧发送给上游提供方，代理仅由个人自行控制。

## 规则

使用明确命名的 `teaching-area-v1` 教学规则：禁止自杀，先提对方棋再检查自身气；实际落子禁止重复“棋盘与下一手执子方”的历史组合；停着豁免重复检查。连续两次停着进入死子确认，有争议可继续下棋，保留历史。

计分为存活棋子加单色边界空区，白方加实际贴目，混合边界为空区中立。提子数不重复加入面积。复杂死活由用户确认或继续下棋解决；保存结果标明用户确认或认输来源，不自动把包围棋算死。

## 检查

`npm run test` 验证规则边界、计分、历史重复、课程变化、开局、SGF 与 AI 回复验证。

本地浏览器检查使用独立 Chrome 会话，不读取个人浏览器档案。需要本机已安装 Google Chrome。

```powershell
node qa/browser-check.mjs
node qa/ai-and-settlement-check.mjs
node qa/proxy-check.mjs
node qa/challenge-and-fallback-check.mjs
npm run test:learning
node qa/scene-lifecycle-check.mjs
npm run benchmark:engine
# 先启动生产预览 npm run preview -- --port 5187
node qa/offline-and-tactics-check.mjs
```

截图和检查报告写入 `.qa/`，该目录不提交。远程 AI 的自动检查采用模拟服务，真实提供方的跨域、模型支持、延迟与费用需以用户配置后的连接测试为准。

## 项目结构

| 路径 | 内容 |
| --- | --- |
| `src/domain/` | 纯棋规、历史、计分、棋谱与测试 |
| `src/content/` | 课程、题库、阶段测评、开局、注解棋谱与挑战范式 |
| `src/components/` | 3D 棋盘、2D 表示、题目和更新提示 |
| `src/views/` | 课程、开局、棋谱研习、小游戏、对弈与复盘 |
| `src/ai/` | 本地策略 Worker、AI 请求与验证 |
| `src/storage.ts` | IndexedDB、设置与导出 |
| `src/archive.ts` | 完整存档校验、棋谱重放验证与进度合并 |
| `scripts/` | 个人本地代理 |
| `qa/` | 实际浏览器流程检查 |
| `docs/` | 需求设计 |

需求设计中的棋力分档自对弈校准、真实手机性能基准、完整人工内容审核与专业引擎接入尚需后续验证，当前版本不宣称正式段位或全局最优判断。
